# 1.4 UI access

## Why it's IP-allowlisted instead of behind auth

Longhorn's web UI has no built-in authentication. Rather than put it behind basic auth or an OIDC proxy, `templates/ui-ingress.yaml` restricts it to an IP allowlist covering the LAN/VPN ranges, enforced by a Traefik `Middleware`:

```yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: longhorn-acl
  namespace: longhorn-system
spec:
  ipAllowList:
    sourceRange:
      - 127.0.0.1/32
      - 10.99.1.0/24
      - 10.99.2.0/24
      - 10.99.99.0/24
      - 10.99.100.0/24
      - 192.168.1.0/24
```

Any request from outside those ranges is rejected by Traefik before it ever reaches the Longhorn frontend pod.

## Ingress

- **Host:** `longhorn.itlusions.nl`
- **IngressClass:** `itl-traefik`
- **TLS:** `letsencrypt-issuer` cluster issuer, cert stored in `longhorn-itlusions-nl-tls`
- **Backend:** `longhorn-frontend` service, port 80

## Verify

```bash
# From an allowed IP range:
curl -I https://longhorn.itlusions.nl/

# From outside the allowlist, expect a Traefik-level rejection, not a Longhorn response
```

If the UI isn't reachable from an address that should be allowed, check `longhorn-acl`'s `sourceRange` against the actual client IP Traefik sees — a VPN or NAT gateway IP may not match what you expect.
