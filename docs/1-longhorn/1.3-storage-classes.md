# 1.3 Storage classes

This chart ships eight `StorageClass` manifests in `itl.longhorn/templates/storageclasses/`, covering every workload tier used across the cluster. All use the `driver.longhorn.io` provisioner except where noted.

## Reference table

| Class | Replicas | Reclaim | Binding | Notes | Use case |
|---|---|---|---|---|---|
| `longhorn` | 3 | Delete | Immediate | Cluster default (`is-default-class: "true"`) | General application storage, non-critical persistent volumes |
| `ha-dbs-lh` | 3 | Retain | Immediate | — | Production databases (PostgreSQL/CNPG, MySQL, MongoDB) |
| `ha-gen-lh` | 2 | Retain | Immediate | — | General HA storage, monitoring, moderate-criticality app data |
| `ha-perf-lh` | 2 | Delete | Immediate | `staleReplicaTimeout: 20`, `dataLocality: best-effort` | High-performance / low-latency workloads |
| `ha-secure-lh` | 2 | Retain | Immediate | `encrypted: "true"` (LUKS), full anti-affinity spread | Sensitive/compliance data at rest |
| `ha-grafana-block` | 2 | Retain | Immediate | `frontend: blockdev` (raw block, no filesystem) | Grafana / time-series raw block storage |
| `dev-single-lh` | 1 | Delete | WaitForFirstConsumer | No redundancy | Development, testing, CI/CD |
| `longhorn-static` | — (upstream default) | Delete | Immediate | Minimal config | Statically-provisioned / pre-provisioned volumes |

## Selection guide

- **Critical production database** → `ha-dbs-lh` (3 replicas, Retain)
- **Sensitive or compliance-scoped data** → `ha-secure-lh` (LUKS-encrypted, Retain)
- **General production app or moderate-criticality data** → `ha-gen-lh` (2 replicas, Retain)
- **Latency-sensitive workload** → `ha-perf-lh` (2 replicas, Delete, best-effort locality)
- **Grafana / time-series on raw block** → `ha-grafana-block`
- **Dev/test, no redundancy needed** → `dev-single-lh`
- **Everything else / unsure** → `longhorn` (cluster default)
- **Pre-provisioned volume** → `longhorn-static`

## Full manifests

Each manifest's own header comments document its parameters in detail — see `itl.longhorn/templates/storageclasses/*.yaml`.

```bash
kubectl get storageclass
kubectl describe storageclass <name>
```
