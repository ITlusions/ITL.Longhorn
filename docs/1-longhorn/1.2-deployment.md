# 1.2 Deployment

## Install / upgrade

```bash
cd itl.longhorn
helm dependency update
helm upgrade --install itl-longhorn . \
  --namespace longhorn-system --create-namespace \
  --wait --timeout 8m
```

The namespace, storage classes, and UI Ingress are all templates in this chart, so one `helm upgrade --install` sets up everything — there's no separate manifest-apply step.

## Why the namespace needs the `privileged` PSA label

Longhorn's CSI driver and engine pods need `hostPath` mounts, device access, and elevated capabilities that this cluster's default `baseline` Pod Security Admission level blocks. This is Longhorn's own documented requirement for Talos, not something specific to this chart.

`templates/namespace.yaml` sets the label directly on creation:

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: longhorn-system
  labels:
    pod-security.kubernetes.io/enforce: privileged
```

This is deliberately baked into the chart rather than relying on `--create-namespace` (which wouldn't set the label) or a later `kubectl label` on an existing namespace. Labeling an *already-existing* namespace as privileged is treated as a security-weakening action and gets blocked by tooling in this environment — creating it privileged from the start avoids that entirely.

## Verify

```bash
kubectl get nodes.longhorn.io -n longhorn-system    # SCHEDULABLE should be true on every node
kubectl get storageclass
kubectl get pods -n longhorn-system
```

A healthy install has every `longhorn-manager`, `longhorn-engine`, and CSI plugin pod `Running` on every node, and `SCHEDULABLE: true` for all nodes in `nodes.longhorn.io`.
